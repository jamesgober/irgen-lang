# irgen-lang v0.2.0 — HIR to ir-lang SSA, the Foundation

**The first crate that feeds the family's own native path.** v0.2.0 turns the
scaffold into a lowering from HIR (hir-lang 0.4), typed by typeck-lang 0.3, to
ir-lang 2.0.0-alpha.2 SSA. The static-explicit subset lowers completely:
functions and signatures, locals as SSA, structured control flow, `match`,
direct calls, records and arrays in memory, every OPS operation with its exact
policy, exceptions through `invoke` and landing pads, `finally` and `defer`,
and GC references relocated at every safepoint. Every function it emits passes
ir-lang's validator, and generated programs agree with an independent
evaluator of the HIR subset and with the bytecode path (bcgen-lang +
bvm-lang).

What it does not do yet, stated plainly: **the output is not compiled to
machine code by this release.** backend-lang 0.3 and opt-lang 0.2 are built on
ir-lang `=2.0.0-alpha.1`, irgen-lang on `=2.0.0-alpha.2`, and one Cargo build
holds one 2.0 pre-release. The native end-to-end test moves to the first
backend-lang release on alpha.2 (recorded in `dev/ROADMAP.md`). Today the
lowered modules run in ir-lang's reference interpreter.

## What is irgen-lang?

The SEMA/CODE bridge of the `-lang` family (ISSUES P29): it owns HIR to
ir-lang 2.0 translation for the native tiers. It does not type-check
(typeck-lang), optimize (opt-lang), or select instructions (backend-lang); the
bytecode path is bcgen-lang's. Its only dependencies are the family's own:
hir-lang, typeck-lang, ir-lang, and intern-lang.

## What's new in 0.2.0

### `lower`, `Lowerer`, `Options`

`lower(&hir, &typed, &names)` returns a `Lowered`: the ir-lang module, and
where each function item, module body, and global went. `Lowerer` with
`Options` picks what run-time errors do (`ErrorMode::Raise`, the default, or
`Trap`) and sets the budgets (lowering steps, global initializer bytes,
statepoint work).

```rust
use hir_lang::{Builder, Name, OpKind};
use intern_lang::Interner;
use irgen_lang::{ErrorMode, Lowerer, Options};
use typeck_lang::{check, Profile};

// fn main() { let x = 1 + 2; }
let mut names = Interner::new();
let mut b = Builder::new();
let (one, two) = (b.int(1), b.int(2));
let sum = b.op(OpKind::Add, &[one, two]);
let x = b.new_binder(Name::new(names.intern("x")), hir_lang::BinderKind::Local);
let pat = b.bind(x);
let stmt = b.let_stmt(pat, Some(sum));
let body = b.block(&[stmt], None);
let main = b.func(Name::new(names.intern("main")), &[], body);
let root = b.module(None, &[main]);
let hir = b.finish(root)?;
let typed = check(&hir, &Profile::static_explicit()).unwrap();

let out = Lowerer::new(Options::new().with_errors(ErrorMode::Trap)).lower(&hir, &typed, &names)?;
let text = out.module().to_string();
// `1 + 2` under overflow = error is a `check`; in trap mode its error edge traps.
assert!(text.contains("check add<overflow=error>") && text.contains("trap 1"));
# Ok::<(), Box<dyn std::error::Error>>(())
```

### Locals as SSA, control flow

Scalar locals and parameters go through ir-lang's variable construction
(`declare_var`/`def_var`/`use_var`/`seal_block`, Braun et al.), and every block
is sealed as soon as its predecessors are known. Blocks with labels and
values, `if`, the loop primitive with its step, labeled `break` and
`continue`, and `return` lower to blocks and edges; code after a jump is
lowered into blocks with no predecessors, which are removed.

### `match` and patterns

A sequential decision procedure over scalars, tuples, and records: literal,
range, constant, binding, wildcard, tuple, constructor, record, and
or-patterns, with guards. A run of guard-free literal arms over an integer or
`char` becomes one `switch`. A `match` with no matching arm raises `NoMatch`
(E0200). `let` takes the same patterns, with `else`.

### Records, tuples, arrays

ir-lang aggregates in stack slots and globals (C layout). Reads of aggregate
places copy, so a value read cannot change later; parameters travel by
address (the callee owns the copy) and results through a hidden first
pointer. Indexing is bounds-checked (`IndexOutOfBounds`, E0102). Global
initializers are evaluated at compile time into bytes; constants are inlined
at each use.

### OPS operations with their exact policies

Each operation carries exactly the policy fields ir-lang requires for its
operand class, and is a `check` where ir-lang's `can_error` says it can fail.
Two places where ir-lang's operations differ from HIR's are bridged: a shift
by an amount of another integer type is converted with the same outcome
under `mask`, `error`, and `saturate`; and a negative exponent under
`overflow = trap` raises `NegativeExponent` as OPS v2 specifies (ir-lang's
`pow` would trap; the bytecode differential found the difference).

### Exceptions, `finally`, `defer`

`throw` allocates an exception record through the one host function lowered
code calls, `__irgen_exception` (layout and tags in `irgen_lang::rt`). Inside
a `try`, `finally`, or `defer` region, calls are `invoke`s whose landing pad
forwards the payload to the region; `catch` arms test the thrown value's
primitive type (or catch everything with `_`, run-time errors included).
Cleanup bodies are lowered once: every exit that leaves one — fallthrough,
`break`, `continue`, `return`, rethrow — records its way out, runs the body,
and continues through a `switch`.

### GC references and statepoints

Values of host (`extern`) types are `ref`s kept in SSA values. ir-lang's
`insert_statepoints` fills every safepoint's GC list and rewrites later uses
to the relocated references, along normal and unwind edges; aggregates and
globals holding a `ref` are refused, since memory is not a GC root.

### Precise refusals

Everything outside the subset is `LowerError::Unsupported { construct, node,
span }`: dynamic values, closures, generics, coroutines, and sum types (the
roadmap's 0.5), and strings, methods, references, intrinsics, and the rest,
each a `Construct` variant, at the first node that uses it.

## Tests and verification

- **Against an independent evaluator.** `tests/common/reference.rs`
  evaluates the HIR subset directly, OPS in `i128` arithmetic and native IEEE
  floats; `tests/common/progs.rs` generates well-typed programs of the whole
  subset (aggregates, exceptions, `finally`, `defer`, host references, every
  operation with random policies). Both error modes are compared on the
  result, the thrown value or error, the trap, and a host trace: 20,000
  programs per long run, no disagreement. Every integer operation is also
  checked over every policy and edge value.
- **Against the bytecode path.** Programs over `i64`, `bool`, and `f64` run
  through bcgen-lang 0.3 + bvm-lang 2.0.0-alpha.3 as well: 10,000 per long
  run, no disagreement after the `pow` fix above.
- **Mutation checks.** Deliberately broken lowerings (a wrong operation, a
  skipped `finally` on unwinding, a missing shift conversion) are caught by
  the standard sweep.
- **Hostile input.** 100,000-deep nests lower on a 1 MiB stack; every budget
  is an error; random budgets on random programs never panic; a 4x larger
  body takes about 4x the time.
