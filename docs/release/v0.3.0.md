# irgen-lang v0.3.0 — The First Native Compile

**HIR now runs as machine code, by the family's own code at every stage.**
v0.3.0 connects irgen-lang to the native path: HIR lowered by irgen-lang,
optimized by opt-lang 0.3, compiled by backend-lang 0.4 to x86-64 machine code
(isa-lang encodes every instruction), loaded into executable memory, and run on
the processor. No Cranelift, no LLVM, no system compiler. The native test
compares every run with ir-lang's reference interpreter and with an independent
evaluator of the HIR subset, and they agree: 24,000 native runs per long run,
no disagreement. This closes ISSUES P37.

The crate also moves to ir-lang 2.0.0-alpha.3, which fixes ISSUES P36 (a
negative `pow` exponent is the `NegativeExponent` error under every
non-`promote` policy), so the exponent pre-test 0.2 carried is gone.

What does not run natively yet, stated plainly: **float arithmetic other than
`pow`** (backend-lang 0.4 refuses float operations, comparisons, conversions,
arguments, and results until isa-lang encodes SSE, ISSUES P11), and
**unwinding through a system unwinder** (backend-lang 0.4 emits no unwind
tables; the test carries its own unwinder over backend-lang's records).
opt-lang and backend-lang are dev-dependencies: this crate's output is still
the ir-lang module.

## What is irgen-lang?

The SEMA/CODE bridge of the `-lang` family (ISSUES P29): it owns HIR to
ir-lang 2.0 translation for the native tiers. It does not type-check
(typeck-lang), optimize (opt-lang), or select instructions (backend-lang); the
bytecode path is bcgen-lang's. Its only dependencies are the family's own:
hir-lang, typeck-lang, ir-lang, and intern-lang.

## What's new in 0.3.0

### The native pipeline, end to end

```rust
use hir_lang::{Builder, Name};
use intern_lang::Interner;
use typeck_lang::{check, Profile};

// fn main() {}
let mut names = Interner::new();
let mut b = Builder::new();
let body = b.block(&[], None);
let main = b.func(Name::new(names.intern("main")), &[], body);
let root = b.module(None, &[main]);
let hir = b.finish(root)?;
let typed = check(&hir, &Profile::static_explicit()).unwrap();

// HIR -> ir-lang -> opt-lang -> x86-64.
let mut module = irgen_lang::lower(&hir, &typed, &names)?.into_module();
opt_lang::optimize(&mut module)?;
let compiled = backend_lang::compile(&module, &backend_lang::Options::sysv())?;
assert!(compiled.function("main").is_some());
# Ok::<(), Box<dyn std::error::Error>>(())
```

Running the result takes a loader that binds irgen-lang's exception allocator
(`rt::EXCEPTION`), backend-lang's runtime symbols (`__lexersketch_trap`,
`__lexersketch_resume`, `__lexersketch_pow_f64`/`_f32`), and the program's host
functions. `tests/common/native.rs` is one, for x86-64 Linux and Windows, and
`examples/native.rs` uses it to run `fib(30)`:

```bash
cargo run --example native
```

### The native end-to-end test

`tests/native.rs` runs, on the processor:

- **Generated programs** from the crate's program generator with floats off:
  every integer OPS operation with random policies, conversions, `if`, loops
  with labeled `break`/`continue`, labeled blocks, `match`, calls, records,
  tuples, arrays with bounds checks, compound assignment and `let_place`,
  globals and constants, `throw`/`try`/`catch`/`finally`/`defer` across calls,
  host calls with a trace, host functions that throw, and (in every other
  program) host GC references across safepoints.
- **Hand-written programs**: recursive `fib`; loops with `break` and
  `continue`; integer `pow` under `error`, `wrap`, and `trap` (a negative
  exponent is error 6 under all three); float `pow` through the runtime,
  reached through `bitcast`; records passed by address and returned through
  the hidden pointer, with array writes and bounds checks; a thrown value and
  a run-time error unwinding through two native frames into `catch`, with
  `finally` and `defer` observed through the host trace, and uncaught ones
  leaving the entry; a throwing host function with a live GC reference; many
  values live across an unwinding call; division and shift policies.

Each runs in both error modes, before and after opt-lang, under the SysV and
Win64 conventions, with and without a frame pointer, and is compared with
ir-lang's interpreter (on the lowered and the optimized module) and with the
reference evaluator: the result, the thrown value or run-time error, the trap
code, and the host trace.

The loader is test support (the library stays `forbid(unsafe_code)`): an entry
thunk assembled with isa-lang, a trap handler, host functions behind veneers
that adapt the calling convention and can unwind, the float `pow` runtime bound
to `ir_lang::ls_pow` on bit patterns (as backend-lang's own tests bind it), and
a **native unwinder**: `__lexersketch_resume` saves the machine state, a walk
over backend-lang's call-site records and frame layouts restores each unwound
frame's callee-saved registers, and the stub enters the landing pad with the
payload in `rax`.

### ir-lang 2.0.0-alpha.3 and `pow`

alpha.3 makes a signed `pow<overflow=trap>` fallible (`can_error`), so irgen-lang
emits it as a `check` like any other fallible operation, and the error edge
carries `NegativeExponent` (6). The 0.2 pre-test (a compare, a branch, and a
raise before the operation) is removed. Behaviour is identical: the long
differential runs (20,000 programs against the reference evaluator, 10,000
against bcgen-lang + bvm-lang) agree, as does the native test.

### ISSUES P43, measured

ir-lang alpha.3's validator is quadratic on a long chain of `check`s whose
error edges join one error block, the shape irgen-lang emits for one function
full of operations that can raise. In release, `lower` of one function of
20,000 checked additions takes about 0.4 s and of 40,000 about 1.6 s, nearly
all of it the final validation (irgen-lang's own work at 40,000 is about
50 ms); opt-lang and backend-lang each take about as long again. The
100k/1M benches are not affected (small functions, wrapping arithmetic).
irgen-lang does not reshape its output: every free reshaping is undone by
opt-lang or keeps the quadratic walk. The numbers are in the README and the
roadmap; the fix is ir-lang's.

## Breaking changes

- **ir-lang `=2.0.0-alpha.2` to `=2.0.0-alpha.3`.** `Lowered::module` and
  `into_module` return alpha.3's `Module`; a caller pinned to alpha.2 must
  move with it.
- The IR for a signed `pow<overflow=trap>` changed shape (a `check`, no
  pre-test); the meaning did not.
- `LowerError::Unsupported`'s message reads "outside the subset irgen-lang
  lowers" (it named 0.2).

## Verification

Run on Windows x86_64, Rust stable (1.95), 1.99, and the 1.85 MSRV:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo +1.99 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
cargo test --release --test differential --test bytecode --test native -- --ignored
```

All green. Counts at this tag: 10 unit tests; 80 integration tests (4 of them
property tests) plus 3 long runs behind `--ignored` (20,000 programs against
the reference evaluator, 10,000 against the bytecode path, 3,000 programs and
24,000 native runs: 15,692 returned, 5,072 threw, 3,236 trapped; no
disagreement); 41 doctests, including every `rust` example in `README.md`,
`docs/API.md`, and these notes. The native programs ran on x86-64 Windows (a
Win64 host running both SysV and Win64 compiled code); the Linux path of the
loader (`mmap`/`mprotect`) is the same code and runs in the Linux gate.

Benchmarks (`cargo bench --bench bench`, release profile, x86_64 Windows,
typeck-lang's check excluded):
